## Session 41 (reported 2026-11-01 18:57 UTC) - the gate is at the root

Route (a) from the Session 40 spec: hook the module's document reader during two real BIND calls and diff the walks.

- The walks are identical at root level for accepted and rejected documents: the stream layer enumerates the root's two values (the inner blob, and blob8) and stops there. For the envelope it then opens the inner blob, parses it, and accepts. For every audio document - definite or indefinite encoding, slice or full-size with correct ints - the inner container is never opened at all. ## Session 43 (reported 2026-11-01 21:37 UTC, corrected/upgraded 21:43 UTC) - the gate has a formula

The first report was written from a partial read (interrupted by a safety check on the note file) and stopped one step short of the real ending; the corrected full read is the record. Treat the session's embedded "next steps" framing from that first partial report as superseded by what follows.

- The reader walks for an accepted and a rejected document are *identical* - same 168 reader hits, same order. Everything diverges at one instruction: the **tenth blob-compare**. In the accepted envelope, compare #10 checks the document's elem2 (the 8-byte blob8) against a value the program computes itself over elem1 - match, accepted. In a rejected doc the genuine blob8 is present, but the computed value differs because elem1 changed - nonzero, and the STATUS 1 machinery follows immediately.
- That one mechanism explains Sessions 40-42 in full: every audio doc failed because any change to the inner blob invalidated a blob8 that was being reused verbatim. The document shape was never the real problem; the check value was. It also explains why the module's own STATUS 0 replies always mint a fresh blob8 alongside rewritten ints.
- An offline fitting battery against seven known-good (inner -> blob8) pairs (HMAC and raw SHA-1/MD5/SHA-256 windows, DES-CBC MACs, the op-11 reply core, CRC/FNV family) hit zero - then live input-capture watched the routine's actual inputs instead of guessing constructions, and captured the computation end to end:
  **blob8 = the first 8 bytes of SHA-1(inner || "ATRAC CD" || a fixed 16-byte trailer).** Sony's check value literally hashes the words "ATRAC CD" into every envelope. The curated record pins the trailer as `010f5000 00040000 00000016 725f9be7`. The formula reproduces all seven known-good pairs (the harness envelope, the module's own reply envelope, and five real records minted on Lola's machine) plus the exact value the module computed to reject the r3 doc.
- Gate already opened in run 252: audio-carrying documents with a correctly minted blob8 **passed compare #10**, slice and full-size both. The execute then died *past* the gate, on a post-gate shape/type judgment before the payload path ran (13 SEH rounds, no accept-side compare, no output) - the smaller, later wall Session 44 took.
